# 独立模块源码目录

Rust/Tauri 独立模块仅在 `modules` 分支的 `modules/` 维护。宿主本体、API 与共享 UI 留在 `toolbox` 分支，原 `QingToolbox.Tauri/native-launcher` 等目录不再保留第二份源码。设备传输位于 `src-tauri/src/device_transfer.rs`，直接编译进宿主进程，不依赖模块目录、加载或启用状态。

现有 `build-tauri-*.ps1` 和模块打包入口兼容保留，但源码通过 `module-sources.mjs` 定位到模块 worktree。分别克隆或 CI 必须设置 `QINGTOOLBOX_MODULES_ROOT` 为模块仓库根目录。源码解析器要求 schema 2 原生官方目录，拒绝旧 WPF 源。

```powershell
$env:QINGTOOLBOX_MODULES_ROOT = 'D:\QingToolbox-modules'
./scripts/build-tauri-modules.ps1
./scripts/package-tauri-modules.ps1 -SkipBuild -Smoke
```

模块 Vue 通过构建别名引用本体 `QingToolbox.WebUI/src/design-system/module/` 的真实组件，不复制组件源码。`src-tauri/resources/modules/` 是开发环境暂存产物，不是源码；正式安装器仍为 host-only。

缓存分别计算模块源码、共享 UI 和输出指纹。独立模块源码改变不要求宿主本体重新构建；发布记录变化、Rust target 和 npm/dist 缓存不触发模块重编译。

官方目录与每模块更新清单位于 GitHub `modules` 分支的 `modules/`。目录 schema 2、宿主 API 1 与进程包格式 `tauri-process-v1` 互相独立。根目录索引连接或校验失败会报告错误；单个模块的更新清单连接或校验失败只禁用该模块并显示原因，不影响其他已验证模块。

模块页的“导入模块”下拉提供“从本地导入”和“从仓库下载”。后者读取官方目录和发布清单，仅展示公开模块。读取 raw 域名失败时，使用 GitHub Contents API 读取同一分支、同一文件；不使用第三方镜像。连接、解析、兼容性问题在弹窗内显示。

下载由 Rust 后端负责，前端只能提交目录中已验证的模块 ID。新包放在 `modules` 分支各模块的 `packages/`，URL 必须绑定官方仓库、完整 Commit SHA、目录、模块版本和文件名；旧固定 Release 地址仍兼容。以后模块更新只提交模块分支，不创建 Tag / Release。raw 失败时可使用 GitHub Contents API 读取同一 Commit、同一文件，部分下载先清空再重试，不拼接流或切换可变分支。限制文件大小，验证 SHA-256，以及 qmod 中的模块身份、版本、API。未通过校验的临时文件删除，不执行包内代码。下载保存到系统下载目录的 `QingToolbox Modules/`，同名文件不覆盖，使用递增后缀。旧工具箱需更新一次本体才能接受这种分支包地址。

点击“下载并安装”后，后台完成下载、大小/SHA-256/身份/API 校验，再自动调用已有 `.qmod` 导入或原子覆盖更新流程。标题栏依次显示下载进度、正在安装；离开模块页不影响任务。安装结束使用工具箱信息弹窗通知，并刷新模块列表；相同或更高的已安装版本不重复覆盖，不降级。新模块只安装，不自动加载或启用；覆盖更新先停用/卸载旧运行实例，成功后也不自动运行。开发暂存模块不被仓库下载覆盖。

仓库自动安装仅允许兼容当前宿主/API/平台的模块；不兼容版本显示原因且不可选，本地导入的 API 不匹配确认流程保持不变。所有包的安装入口与删除操作串行化，前端只传模块 ID，不提交下载地址或安装路径。安装失败时保留已校验下载文件供本地导入，不提前提示安装成功。

## 启动与定期更新检查

Rust 宿主使用两个独立后台线程检查工具箱与本地已安装模块。模块检查先读取官方 `modules` 分支 `modules/index.json`，按本地模块 ID 查找对应目录的 `update.json`；只请求已安装且未关闭自动检查的模块，不按名称猜测目录。成功读取目录但找不到 ID 时，详情显示“该模块未在官方仓库中记录”；网络或清单解析失败使用独立错误状态，一个模块的清单失败不阻断其他模块。

设置→启动提供工具箱/模块启动检查开关与各自检查间隔。默认启动检查均开启，工具箱每 360 分钟、模块每 60 分钟检查；间隔允许 5–10080 分钟，`0` 关闭定期检查而不改变启动检查开关。定时器使用单调时钟，运行中修改间隔会生效；检查下载/安装忙时稍后重试，正常失败等待下一检查周期，不持续重试网络。开发环境仍禁止工具箱正式更新下载，模块检查不受此限制。

每个模块详情可单独关闭自动检查，设置按当前环境持久化。后台跳过该 ID，关闭时使在途结果失效；手动检查仍可使用。检查仅更新状态和可用版本，绝不自动下载或安装。用户在详情点击“下载并安装”时重新核对官方清单，再使用与仓库下载相同的验证及原子覆盖流程；只有兼容的更高版本可覆盖用户安装模块。标题栏全局显示进度，更新成功后刷新本地版本，不再要求二次点击安装。

迁移两边的改动需要协调提交，CI 需同时检出匹配的两个分支。
