# QingToolbox 0.3.2-alpha

The second Rust/Tauri 2/Vue 3 host preview, after the published `v0.3.0-alpha`. `0.3.1-alpha` was an internal iteration that was never published, so this release carries everything added since `v0.3.0-alpha`. It is **unsigned**; Windows may show an Unknown publisher or SmartScreen warning. Download only from this repository's GitHub Release and verify the supplied SHA256 sidecar.

## What's new

- **PC device discovery and pairing.** Peers on the local network are found over mDNS and paired with a Noise handshake, so two hosts need neither a broker nor a hand-typed address. The eight-digit pairing code is shown by both sides. Forwarded device notifications arrive in their own popup surface.
- **The Devices page owns transfer and receive settings** instead of a separate QingTransfer window.
- **The shell's appearance reaches module windows.** The light/dark choice is now separate from the appearance preset, and the host publishes it as page attributes before a module's own scripts run, so a module follows the shell without listening for anything and never paints once in the wrong appearance.
- **A local message popup can be fired from the settings page,** so the popup corner, animation and duration can be judged without a paired device having to send something first.
- **Every module manifest declares `apiVersion`,** and the host checks it when a module is imported, so it can refuse one built against an API it does not implement.
- **A development host keeps its own profile namespace and window bounds,** so a debug build stops sharing state with an installed one.
- Qing Launcher reports the Everything index state in its header.
- **Standalone `.qmod` module delivery is restored.** The host Release is host-only, and official modules are installed and updated from their own `.qmod` packages.
- Retired the superseded WPF-era development entry points (`run-legacy-wpf.bat`, `scripts/publish-preview.ps1`, `scripts/run-latest.ps1`, `scripts/stop-dev-host.ps1`, `scripts/measure-startup.ps1`).
- Fixed the pinned-qpdf checksum byte comparison on Windows checkouts, so a line-ending conversion can no longer fail verification.
- CI release smoke runs non-interactively, so a pipeline can no longer wait on input.

## Install and compatibility

Use `QingToolbox-0.3.2-alpha-win-x64-tauri-setup.exe` on Windows x64. Exit QingToolbox completely before installation. The installer and the matching `.sha256` file are the host Release assets; verify the checksum before running the installer.

The installer is **host-only** and contains no bundled modules. Official modules are delivered as separate `.qmod` packages under their own pre-release tags and are imported through the host. Do not import an older WPF `.qmod` into this host; that module ABI is not compatible.

Upgrading an installed `v0.3.0-alpha` in place: the installer first migrates that release's bundled modules into `%LOCALAPPDATA%\QingToolbox\Modules`, backs up a same-id legacy WPF module under `%LOCALAPPDATA%\QingToolbox-MigrationBackups\TauriModules-*` before replacing it, and only then removes the old host-owned `resources` tree. User settings, modules and module data are preserved.

This is an alpha release. It is not code-signed, and real-user upgrade, repair, uninstall and SmartScreen behaviour may vary by environment. Report issues with the installed version and whether this was a clean install or an upgrade.

## Known limitations

- Device-to-device file transfer is driven by the Devices page, but its engine only exists in a development host today. An installed `0.3.2-alpha` has device discovery, pairing and notification popups without it.
- Module-window theming currently reaches Text Tools, which imports the shell's token stylesheets. The other modules still paint from their own stylesheets.
- `qing.qingtransfer` is no longer offered as a user-facing tool card.
- The host remains unsigned, and the stable Module API is not frozen.
