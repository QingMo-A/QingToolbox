# Plan 013：QingToolbox 宿主更新与一键原地升级

**状态：Approved / In Progress — 013A and 013B Implementation Complete; next 013C**
**目标分支：`toolbox`**  
**批准决策：QingToolbox 停止将便携版作为正式分发形态，后续正式发布仅提供安装版。**

## 1. 背景

QingToolbox 已经具备可靠的 Inno Setup 原地覆盖安装能力：

- 固定应用 `AppId`；
- 自动发现已有安装目录；
- 更高版本覆盖低版本；
- 同版本 Repair；
- SemVer 降级保护；
- 安装时关闭目标目录中的旧 Shell；
- 安装成功后从同一目录恢复新版 Shell；
- 保留设置、用户模块、模块数据、缓存和启动授权；
- 精确清理旧版本不再拥有的宿主文件；
- 保留安装目录中的未知用户文件；
- 保持单一卸载入口和快捷方式集合。

当前缺少的是应用内完整入口：

```text
检测官方新版本
→ 向用户提示
→ 用户点击下载
→ 验证官方安装器
→ 用户确认安装
→ 启动现有安装器
→ 原地覆盖并重新打开新版
```

本计划不重新实现宿主文件替换，也不建立第二套升级事务。应用内更新只负责发现、提示、下载、验证和启动官方安装器，真正的覆盖升级继续由现有安装器完成。

## 2. 唯一主要目标

为 QingToolbox 增加基于官方 GitHub Release 的宿主版本检测、更新提示、官方安装器下载验证，以及用户确认后的一键原地升级。

最终必须同时支持两条等价路径：

### 路径 A：应用内更新

```text
QingToolbox 检测官方 Release
→ 显示新版本提示
→ 用户点击下载
→ 校验官方安装器
→ 用户点击立即更新
→ 启动安装器
→ 原地覆盖并重新打开
```

### 路径 B：用户手动下载安装器

```text
用户自行下载更高版本安装器
→ 双击运行
→ 安装器识别原安装目录
→ 原地覆盖并重新打开
```

两条路径必须共用相同的版本、安装目录、数据保留、Repair 和降级保护语义。

## 3. 产品分发决策：取消正式便携版

从 Plan 013 开始，QingToolbox 的正式 Windows 分发形态统一为安装版。

### 3.1 对外发布规则

后续正式 Release：

- 发布 `win-x64` 安装器；
- 发布安装器同名 `.sha256`；
- 不再发布便携 ZIP；
- 不再宣传便携模式；
- 不再把便携 ZIP 作为发布门禁产物。

已发布的历史 Release、tag 和资产保持不变，不追溯删除或替换。

### 3.2 内部构建边界

取消便携版不等于删除所有 `dotnet publish` 或宿主载荷审计逻辑。

仍允许保留：

- 安装器 payload 的内部 publish 目录；
- Host Payload Manifest；
- Web 资产绑定验证；
- 安装器输入载荷审计；
- 测试使用的临时发布目录。

应移除或停止使用的仅是“面向用户的便携 ZIP 分发、文档、上传和对应 Release 资产要求”。不得为了取消便携版顺手重写整个发布流水线。

### 3.3 非标准部署

正式自更新只支持具有有效 QingToolbox 安装记录的安装版。

当程序目录与固定安装记录不一致，或用户复制安装目录后直接运行时：

- 不允许自动启动覆盖安装；
- 显示“当前部署方式不支持一键更新”；
- 允许打开官方 Release 页面或下载官方安装器；
- 不把非标准目录自动转换为受支持安装目录；
- 不直接覆盖当前运行目录。

## 4. 用户可见成果

### 4.1 自动更新提示

Production 启动完成后进行非阻塞检查。发现新版本时显示克制的全局提示，不使用每次启动都阻塞用户的模态框。

示例：

```text
QingToolbox 0.3.0-alpha 已发布
当前版本：0.2.0-alpha

[稍后] [查看更新]
```

### 4.2 关于与更新区域

在当前 Production 原生设置/关于界面增加“关于与更新”区域，至少显示：

- 当前版本；
- 最新版本；
- 发布日期；
- 简短更新说明；
- 上次检查时间；
- 手动检查按钮；
- 下载进度；
- 验证结果；
- “下载并安装”或“立即更新”按钮。

Plan 013 不要求开放 Production Web UI，也不得以宿主更新为理由扩建 Production Web Bridge。

### 4.3 下载与安装反馈

下载阶段显示真实字节进度：

```text
正在下载安装程序
38.4 MB / 62.1 MB
```

验证完成后显示最终确认：

```text
安装程序已验证

安装更新将关闭 QingToolbox 和当前打开的模块窗口。
设置、用户模块和模块数据会被保留。

[取消] [立即更新]
```

用户确认后启动官方安装器。应用不得自行删除或替换正在运行的宿主文件。

## 5. 更新源与版本选择

### 5.1 唯一可信更新源

只允许使用：

```text
QingMo-A/QingToolbox 官方 GitHub Release
```

不得使用：

- `toolbox` 分支最新 commit；
- GitHub Actions 临时 Artifact；
- 未发布 tag；
- Draft Release；
- 第三方镜像；
- 用户自定义更新地址。

普通代码推送不等于软件发布。

### 5.2 Release 选择规则

第一版根据当前版本成熟度选择更高版本：

- Alpha 可发现更高的 Alpha、Beta、RC 和 Stable；
- Beta 可发现更高的 Beta、RC 和 Stable；
- RC 可发现更高的 RC 和 Stable；
- Stable 默认只发现 Stable；
- Draft 永远忽略；
- 相同版本不显示为更新；
- 更低版本不显示为更新。

版本比较必须使用统一的 SemVer 实现，不得使用字符串比较。第一版不增加更新频道设置。

## 6. 官方发布资产契约

每个可安装 Release 必须包含且只选择一组目标资产：

```text
QingToolbox-{version}-win-x64-setup.exe
QingToolbox-{version}-win-x64-setup.exe.sha256
```

应用内更新必须验证：

1. Release tag 可以解析为合法 SemVer；
2. 安装器文件名中的版本与 Release tag 一致；
3. 恰好存在一个目标架构安装器；
4. 存在完全同名的 `.sha256`；
5. sidecar 格式严格合法；
6. sidecar 中记录的文件名完全匹配；
7. 安装器大小处于明确上限内；
8. Content-Length 与实际长度一致；
9. 下载完成后的 SHA256 完全匹配；
10. 验证失败的文件永远不得启动。

现有 `resolve-previous-preview-installer.ps1` 的官方资产数量、命名和 sidecar 校验语义应作为实现参考，避免出现第二套不一致规则。

SHA256 用于检测下载损坏和资产错配，不声称能够抵御官方仓库或发布账户被攻破。代码签名信任链属于后续发布安全增强，不阻塞本计划。

## 7. 环境边界

### Production

- 允许自动检查官方 Release；
- 允许显示更新提示；
- 允许用户下载、验证和启动安装器；
- 必须要求用户明确确认安装。

### Development

- 不得默认污染 Production 的更新缓存和检查时间；
- 使用隔离缓存和可注入 HTTP/Release 测试源；
- 默认不得把开发构建误判为可正式升级版本；
- 可以提供明确的开发测试入口，但不增加公开的自定义更新源设置。

### ModuleTest

- 不访问真实 GitHub Release；
- 只使用本地或注入的确定性测试数据；
- 不启动真实安装器。

## 8. 阶段拆分

## 013A：安装版唯一分发契约

**状态：Implementation Complete**

### 目标

停止正式便携版分发，并把发布、文档和门禁统一为安装器优先，而不重构安装器内部载荷生成。

### 范围

- 移除后续 Release 对便携 ZIP 和 ZIP sidecar 的发布要求；
- 调整发布元数据，不再把便携文件名作为对外产品资产；
- 更新 README、发布文档和总开发计划；
- 调整 CI/RC Gate 中面向用户的便携资产上传和验收；
- 保留安装器 payload 的内部 publish、Manifest 和审计能力；
- 增加“正式 Release 只包含一组安装器与 sidecar”的针对性验证。

### 不包括

- 删除全部 publish 脚本；
- 重写安装器；
- 修改模块发布协议；
- 创建新 Release；
- 删除历史 Release 资产。

### 完成标准

- 后续发布流程不再产生或上传正式便携 ZIP；
- 安装器构建和升级测试继续工作；
- 文档不再向用户推荐便携版；
- 内部宿主载荷审计仍然可用。

## 013B：Release 检测与更新提示

**状态：Implementation Complete**

Production 在首屏稳定后执行低优先级官方 Release 列表检查，并在 24 小时成功缓存、
ETag/Last-Modified 条件请求、并发合并和环境隔离边界内选择最高适用版本。原生设置页
显示“关于与更新”，新版本通过非模态横幅提示。Development 与 ModuleTest 默认不访问
真实 GitHub。013B 不下载 sidecar 或安装器，也不启动安装流程。

### 目标

增加宿主版本检测和用户可见提示，但不下载、不安装。

### 范围

- 新增宿主更新检查服务；
- 查询官方 GitHub Release 列表；
- 解析和比较 SemVer；
- 忽略 Draft 和不适用版本；
- 使用 ETag/Last-Modified 或等效条件请求；
- 缓存上次成功检查时间和已确认结果；
- Production 启动后延迟检查一次；
- 设置/关于区域支持手动检查；
- 显示全局更新横幅；
- 显示当前版本、最新版本和受限长度的 Release 摘要。

### 默认频率

```text
启动后延迟检查一次
→ 距离上次成功自动检查不足 24 小时则跳过

手动检查
→ 不受 24 小时限制
```

### 不包括

- 安装器下载；
- 自动安装；
- 更新频道设置；
- GitHub 登录；
- 强制更新。

### 完成标准

- 新版本能够稳定发现；
- 无更新时不打扰用户；
- 网络失败不影响主程序启动；
- 断网时可以显示上次已确认状态并明确标注缓存；
- 重复检查合并为一个底层请求；
- 中英文文案完整。

## 013C：安装器下载与 SHA256 验证

**状态：Next — Not Started**

### 目标

让用户在应用内下载并验证官方安装器，但暂不启动安装。

### 范围

- 下载目标 Setup 与同名 SHA256 sidecar；
- 写入环境隔离的宿主更新缓存目录；
- 未完成文件使用临时名称或扩展名；
- 显示真实下载进度；
- 支持用户取消；
- 限制最大响应和文件大小；
- 校验 Content-Length；
- 严格解析 sidecar；
- 计算本地 SHA256；
- 校验成功后原子提交为已验证安装器；
- 失败或取消后清理不完整文件；
- 已验证的相同 Release 资产可以安全复用。

### 最小状态

```text
Idle
Checking
UpdateAvailable
Downloading
Verifying
ReadyToInstall
Failed
```

不得为了本功能新增复杂更新事务状态机。

### 不包括

- 自动后台预下载；
- 分片下载；
- 断点续传；
- P2P；
- 第三方下载源；
- 数字签名基础设施；
- 增量补丁。

### 完成标准

- 未验证安装器绝不进入可安装状态；
- Hash 错误明确提示并删除失败文件；
- 取消不会留下可执行半成品；
- 重复点击不会创建重复下载；
- 下载失败不自动连续重试。

## 013D：安装器交接与端到端原地升级

### 目标

用户确认后启动已验证的现有安装器，完成一键原地覆盖；同时继续保证手动运行更高版本安装器可以独立升级。

### 范围

- 确认当前进程属于有效安装版；
- 启动前再次验证安装器身份、长度和 SHA256；
- 显示最终关闭确认；
- 通过现有安装器完成升级；
- 安装器成功创建进程后才允许进入应用退出流程；
- 安装器启动失败时 QingToolbox 继续运行；
- 防止重复点击启动多个安装器；
- 保留手动更高版本覆盖、同版本 Repair 和降级保护；
- 增加应用内路径的端到端升级验证。

### 建议启动参数

第一版优先使用：

```text
/SILENT /NORESTART
```

目标是保留可见安装进度，同时避免再次要求用户选择安装目录。不得默认使用完全不可见的强制静默安装。

最终参数必须以真实 Inno Setup 行为和现有升级测试结果为准，不得仅凭假设固定。

### 不包括

- QingToolbox 直接覆盖自身文件；
- 独立 Update Helper；
- Windows Service；
- 强制后台更新；
- 无提示关闭用户窗口；
- 宿主文件级自动回滚系统；
- 重写现有 Inno Setup 安装器。

### 完成标准

应用内路径：

```text
检查
→ 下载
→ 验证
→ 用户确认
→ 安装器启动
→ 旧版退出
→ 新版从原目录启动
```

手动路径：

```text
双击更高版本安装器
→ 自动识别原安装
→ 覆盖
→ 新版启动
```

两条路径最终必须产生相同的安装目录、卸载记录、快捷方式、数据保留结果和版本记录。

## 9. 交互规则

### 自动检查

默认开启，不在第一版增加关闭开关：

- 频率低；
- 不自动下载；
- 不自动关闭；
- 不自动安装；
- 检查失败不影响使用。

### 用户控制

必须由用户明确触发：

```text
下载
安装
```

自动检查不得自动进入下载。

### “稍后”

点击后：

- 当前运行周期不再显示横幅；
- 设置/关于区域仍可看到更新；
- 下次满足检查间隔后可以重新提醒。

第一版不加入永久“忽略此版本”。

### 更新进行中

- 下载或校验时禁止重复发起；
- 下载阶段允许取消；
- 校验阶段不伪造下载进度；
- 不提供虚假的暂停功能；
- 不在用户工作时自动关闭 Shell。

## 10. 安全与可靠性边界

必须保持：

- 更新请求只访问官方仓库和所选官方 Release 资产；
- 下载目标由经过验证的 Release 元数据决定；
- UI 不接收或提交任意本地路径；
- 安装器缓存与安装目录分离；
- 下载文件不写入 `{app}`；
- 不完整文件不可执行；
- SHA256 未通过不可启动；
- 解析歧义一律安全拒绝；
- 启动安装器前执行最终文件复核；
- 缓存不能仅凭文件名被信任；
- 手动下载的安装器继续由安装器自身 SemVer 和目录规则保护；
- 不修改 B1/B2.1、模块事务、模块更新协议或 Production Web 边界。

## 11. 故障处理

### 检查失败

显示“暂时无法检查更新”，不阻塞启动。

### Release 结构无效

显示“该版本缺少有效的官方安装程序”，不提供安装按钮。

### 下载失败

显示失败原因和“重试”，不自动连续重试。

### Hash 不匹配

显示“安装程序验证失败，文件已被丢弃”，并删除失败文件。

### 安装器无法启动

QingToolbox 继续运行，并显示“无法启动安装程序”。不得先关闭 Shell。

### 安装失败

由现有安装器日志负责诊断。QingToolbox 下次启动时重新检查版本，不把启动过安装器等同于升级成功。

013A、013B 和 013C 的普通提交不重复运行完整安装器发布门禁。

## 13. 明确不做

Plan 013 不包含：

- 检测远程分支最新 commit；
- 自动安装每次推送；
- 无用户确认的静默更新；
- 强制更新；
- 后台 Windows Service；
- 独立更新守护程序；
- 增量或差分补丁；
- 第三方镜像；
- 更新频道设置；
- 多架构下载；
- 便携 ZIP 自更新；
- 数字签名 PKI；
- 宿主自动回滚系统；
- 模块更新逻辑改造；
- B1/B2.1 修改；
- Production Web UI。

## 14. 阶段停止条件

满足以下条件后，Plan 013 结束并冻结：

```text
正式发布只保留安装器分发
能可靠发现官方新版本
能向用户显示更新
能下载并验证官方安装器
用户确认后能启动覆盖安装
更高版本手动安装器仍能覆盖
同版本 Repair 仍有效
低版本安装器仍被拒绝
设置、模块和用户数据继续保留
没有已知 P0/P1 问题
```

完成后，下列内容默认进入技术债，不阻塞后续用户工具功能：

- 断点续传；
- 下载镜像；
- 永久忽略版本；
- 自定义更新频道；
- 增量更新；
- 数字签名；
- 更新历史页面；
- 宿主自动回滚。

## 15. 任务与提交规则

每轮 Codex 任务必须只有一个主要目标：

1. `013A`：取消正式便携版分发；
2. `013B`：Release 检测与提示；
3. `013C`：下载与验证；
4. `013D`：安装器交接与端到端升级。

不得把四轮实现压进一次提交，也不得顺手重构模块事务、Web Shell、启动恢复或安装器核心。

每轮必须：

- 先审查并保留用户未提交修改；
- 只修改 `toolbox` 分支；
- 运行与本轮范围匹配的测试；
- 执行 `git diff --check`；
- 普通提交并推送 `origin/toolbox`；
- 不 amend；
- 不 force push；
- 不创建 tag 或 GitHub Release；
- 报告修改内容、测试结果、Commit SHA、Push 结果和遗留问题。
